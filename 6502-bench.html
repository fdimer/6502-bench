Screen

Click the picture and type. Letters, digits and symbols go to the PET key with that character, whatever your keyboard layout; hold Shift with a letter for its graphics character. Enter is RETURN, Backspace is DEL, Esc is STOP, Home is HOME (Shift+Home clears the screen), Insert is INST, Tab is RVS, the arrow keys move the cursor, ^ is the up-arrow key and _ the left-arrow key. The keyboard above is laid out like the PET's own; the graphics character each key gives with SHIFT is drawn on its front face from the character ROM, and SHIFT stays down for the next key. Load ROM folder asks for the folder that holds your ROM files and fits the ones the chosen BASIC needs; the files must keep their standard names: basic-2-c000, basic-2-d000, edit-2-n and kernal-2 for BASIC 2; basic-4-b000, basic-4-c000, basic-4-d000, edit-4-n and kernal-4 for BASIC 4; characters-2 for both. The row of sockets shows which file sits in each ROM socket on the board. Click a socket to fit a ROM of your own there instead, whatever it is called: a different editor, a patched kernal, or an option ROM in the spare sockets UD3 and UD4. Load program puts a .prg file straight into memory: wait for READY, load it, then type RUN. The ROMs are not included; your browser keeps them once loaded.

Memory chips live pins · click a pin for its fault menu

Every memory chip on the board, from the 320351 parts list and layout and the 320349 logic diagram: the sixteen 4116 dynamic RAMs (UI2–UI9 and UJ2–UJ9, one per data bit in each 16K bank), the two 2114s of the screen RAM (UF7, UF8), the ROM sockets UD3–UD9 and the character generator UF10. A tile's dot lights while its chip is being accessed. Click a tile to see that chip's pins, which follow the bus on every clock; the screen RAM and the character generator show the video circuit's own reads between CPU accesses. UI is the bank at 0000h and UJ the one at 4000h; position 9 holds data bit 0 and position 2 bit 7; UF8 holds screen bits 0–3 and UF7 bits 4–7.

To simulate a fault, click a pin for its menu. A pin on a line shared with other chips gets a tick box: without it, the buttons hold the whole line high or low, and every pin on that line, on every chip, sees the level; with it ("Disconnected from the line"), the fault is on this chip's pin alone. A pin with a line of its own has the plain choices: Disconnected (an input then floats high), High or Low. An address pin fault makes the chip use the wrong cell; a data pin fault changes that bit on reads and writes; chip select held high (or a fault on RAS or CAS of a dynamic RAM) takes the chip out of circuit; write enable held high loses writes, held low turns every access into a write. A chip with a fault is marked in red, and every fault is listed in the Debug panel, where it can be removed. The memory view and the disassembly show what the CPU reads through the faults.

Clicking φ0 pulses one clock; right-click it for its fault menu. Every other ringed pin opens the fault menu: on a line shared with other chips, hold the whole line high or low, or tick "Disconnected from the line" for a fault on this pin alone; a pin with a line of its own can be disconnected (it then floats high) or held high or low. On the PET the 6502 (UC4) reaches most of the machine through buffers: its address pins feed BA0–BA15 through UC3 and UB3, and its data pins share D0–D7 with the ROM sockets, the PIAs and the VIA (see the Memory chips panel). Faults are listed in the Debug pane and stay until cleared there, in the Memory chips panel, or by Master reset.

Program

Standard 6502 syntax, one instruction per line. Labels start in the first column or end with :; comments start with ;. Directives (dot optional): .org or * =, = or EQU, .byte, .word, .res, .end. Numbers: $1F, %1010, 42, 'A'; * is the current address; <label and >label give its low and high byte. Zero-page addressing is used automatically when the address is known to be below 0100h; write it with four digits ($0012) to force absolute. Code starts at the Load at address; an .org in the source overrides it. Import a file with the button or by dropping it on the editor.

Hex bytes separated by spaces or newlines. Text after ; is ignored. Write FFFA: to continue loading at another address. Intel HEX files (lines starting with :) are also accepted and keep their own addresses. Raw binary ROM images (.bin, .rom) import here as hex. Scroll through all 64 KB. Click a byte to edit it (ROM too). Blue marks the instruction being executed, amber marks bytes written by the last instruction, underline marks the top of the stack. ROM is tinted; I/O registers show the value a read would return. With Follow PC ticked, each step brings the current instruction back into view; untick it to keep watching another area.

Memory bitmap

Point at the bitmap to read a byte; click to show it in Memory.

Every bit of memory is one pixel. Each byte is a row of 8 pixels (bit 7 on the left) and each strip is one 256-byte page, read top to bottom. The background colour shows what each part of RAM is used for, read from BASIC's own pointers, so you can watch a program, its variables and its strings grow. The character ROM is shown too: every character is 8 bytes, so its shapes are visible. The red mark is the program counter and the blue mark the stack pointer.

    Starred cycles (rd*, wr*) are dummy accesses the 6502 makes while it works out an address or modifies memory; real hardware sees them, so they matter for I/O registers.

    PET hardware PIAs · VIA · video

    PIA 1 (E810h) scans the keyboard: port A bits 0–3 pick a row, port B reads its eight keys. Its CB1 input is the VIDEO ON signal from the video counters; the falling edge at the end of each picture is the 60 Hz interrupt that runs the keyboard scan and the clock. PIA 2 (E820h) is the IEEE-488 data bus. The VIA (E840h) has the IEEE-488 control lines, the cassette lines, the user port, the character-set select on CA2 (POKE 59468,14 for lower case, 12 for graphics) and CB2, where sound comes out.

    System memory map

    The defaults follow a common hobby layout: 16 KB RAM at 0000h, a 6522 VIA at 6000h and ROM from 8000h to FFFFh, which holds the NMI, reset and IRQ vectors at FFFA–FFFFh. The 6502 has no separate I/O space, so peripherals sit in the memory map.
